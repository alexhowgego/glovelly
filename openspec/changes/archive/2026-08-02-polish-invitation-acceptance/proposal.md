## Why

Invited users already receive a clickable login link, but its generic "Open Glovelly" wording does not clearly communicate that following it accepts their invitation through the secure Google sign-in flow. Issue #188 identified this as avoidable friction in an otherwise supported enrolment journey.

## What Changes

- Present the invitation email's primary HTML CTA as accepting the invitation and signing in, with copy that clearly identifies the Google email address the recipient must use.
- Preserve an accessible plain-text fallback URL and equivalent acceptance guidance for email clients that cannot render the button.
- Verify the invitation email CTA and document the recipient's first-login enrolment journey in automated and UAT coverage.
- Preserve the existing security model: Google authentication and verified-email matching remain necessary before a pre-provisioned user is enrolled; possessing the email link alone never grants access.

## Capabilities

### New Capabilities
- `invitation-acceptance`: Clear, secure recipient invitation acceptance through the existing Google sign-in and first-login enrolment flow.

### Modified Capabilities

- None.

## Impact

- Invitation email content generated by `backend/Glovelly.Api/Endpoints/AdminEndpoints.cs`.
- Admin invitation endpoint integration tests and enrolment UAT documentation.
- No new API, data model, identity provider permission, or external dependency.
